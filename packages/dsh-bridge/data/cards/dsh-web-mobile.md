## 2. Verdict in one sentence

Nothing hostile found: the shipped product is a client-side CSS/DOM shell plus a host-side response compressor with zero live network egress beyond your own loopback DSH instance, and every scanner alarm traced to a dev-only probe script or bundler mechanics - but the audit was single-model without behavioral probing, so the pipeline ceiling holds the card at C.

## 5. What we could not check

- **Behavioral probe.** Nothing was executed against a live DSH instance; the
  prototype-patch restore path was verified by reading, not by unload/reload testing.
- **Published parity.** No registry tarball comparison; GitHub installs compile at pack
  time from whatever HEAD is then, so future commits are out of scope.
- **Client-side DOM effects exhaustively.** Effects were spot-checked (stylesheet,
  reparent helpers listed under src/client/effects/); each is page-DOM manipulation, but
  not every one was line-read.
- **Upstream fork provenance.** The compression feature credits community fork
  wzxmt-zhc/dsh-web-mobile v2.5.0 (README changelog); that lineage was not diffed.

## 6. Reviewer disagreement

Single-reviewer pass (one model, no second adversarial model). Per pipeline rules this caps
the grade at C regardless of findings; the substantive case would argue higher (zero egress,
tiny attack surface, dev tooling quarantined outside the shipped bundle). The scanner's F
disagreed; the gap is fully explained by import-heuristic false positives on zlib/http and
dev-script co-occurrence gating.

## 9. Strengths

1. Minimal host footprint: the Node half is one wrapper function registering one disposer (src/index.ts:15-21), which makes the trust question small enough to actually answer.
2. Compression is content-transforming only: it never originates connections, never buffers to disk, and restores the patched prototype on unload.
3. Dev tooling (CDP probe) is quarantined under scripts/ with loopback defaults and never imported by shipped code.
4. Client effects are declarative DOM/CSS registration through the documented slots/effects API rather than ad-hoc global mutation.
5. Honest changelog crediting the community fork it ports features from (README, Unreleased section).

## 10. Residual risks

1. The process-wide `ServerResponse.prototype` patch touches every HTTP response the web profile serves, including routes owned by other plugins; a bug here corrupts neighbors, though the 4 KiB JSON-only gate bounds exposure.
2. GitHub-install means the code you run tomorrow is whatever lands on default branch HEAD; this card covers only the pinned commit.
3. Mobile shells that reparent DOM nodes (effects/git-chip-reparent, settings-toolbar-reparent) can break or be abused by future host UI changes in ways a static read cannot predict.
4. The bundled prebuilt lib/client.js is committed alongside sources; parity between the two is asserted by a build check, not verified byte-for-byte in this audit.

## 11. Re-verify steps

1. Re-run section 7 against current HEAD; any new absolute URL constant in src/ or lib/index.js must be re-adjudicated before trusting an update.
2. Diff src/compress.ts after updates; new codecs, new size gates, or removed dispose logic warrant a re-read.
3. Watch for the dev probe migrating from scripts/ into lib/ or package exports; that would move it into the trusted surface.
