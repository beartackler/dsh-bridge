## 2. Verdict in one sentence

The DSH adapter itself is exemplary - loopback-only token-gated delivery of a content-free projection that never touches credentials - but installing Petdex means adopting a whole desktop companion whose hook layer reads every tool event your agents emit, ships opt-out telemetry, auto-updates from its own endpoint, and documents a `curl | sh` pet-install path.

### Provenance, verified end to end

This is the strongest supply-chain story in the catalog so far: the tarball the desktop app installs
is embedded in the Zig binary, hashed against a constant in source, re-hashed after write, installed
with `--ignore-scripts`, byte-identical to the reviewed sources, and pinned to an exact dsh CLI
version channel (dsh_integration.zig:8-9, 60-98).

## 5. What we could not check

- **Published npm artifact** `@petdex/dsh-plugin@0.1.0`: the registry copy was not pulled for byte
  comparison against this commit; the verified equality covers the repo-embedded tarball only.
- **Behavioral probe.** No live mount of the bridge into a running harness (pipeline S4 unavailable).
- **Cross-model review.** Single reviewer.
- **Desktop binary builds** (Zig -> signed app artifacts) were not reproduced from source.
- **Server-side platform** (Vercel routes, workers, R2) reviewed statically at its security
  boundaries only; runtime behavior of the hosted service is out of scope for a commit pin.

## 6. Reviewer disagreement

Single-reviewer pass. Scanner says F; this card says C. The gap: both criticals are CI
self-provisioning and an SSRF-guard test, the cred-plus-net pairing does not exist in the DSH
adapter, and the tarball provenance is verifiably clean. Held at C rather than B because the graded
subject is inseparable from a desktop companion whose hook layer sees every tool event across all
your agents, telemetry is opt-out, updates flow from the vendor's endpoint automatically, and no
probe or second reviewer ran.

## 9. Strengths

1. Content-free projection is enforced in code, not just documented: the normalizer maps events to
   fixed display strings and identifiers, and nothing else crosses the boundary
   (integrations/dsh/src/normalize.js:1-34; README.md:43).
2. Delivery fails closed toward DSH: 300 ms timeout, silent error swallowing, bounded queue -
   Petdex can degrade itself but never stall or alter the harness (index.js:53, 88-97, 122-127).
3. Tarball integrity is enforced twice in native code and survives to a byte-identical comparison
   against reviewed sources (dsh_integration.zig:95-116).
4. The install chain passes `--ignore-scripts` to the harness package manager
   (dsh_integration.zig:69).
5. Submission-side SSRF/script-injection defenses are layered and tested, including an explicit
   test that the metadata IP is refused (security.test.ts:87; install-script.ts:33-45).

## 10. Residual risks

1. The desktop hook layer receives every tool-lifecycle event (and prompt-derived titles) for all
   integrated agents, concentrating cross-agent behavioral metadata in one companion app
   (bubble-runner.ts:31-48).
2. Telemetry defaults to on with opt-out, sending install/version/os/command counters to
   petdex.dev (telemetry.ts:1-14).
3. The desktop app polls the vendor's release endpoint and presents/downloads updates; the served
   artifact is outside any commit this card pins (updates.zig:4-11, 64-76).
4. Documented skill setup fetches SKILL.md from the default branch over `curl`, pinning neither
   revision nor hash (docs page.tsx:508).
5. The npm registry copy of the plugin was not compared against the audited tree; registry
   installs trust the publisher at click time.

## 11. Re-verify steps

3. Re-vet at 90 days, at the next desktop release changing `hook_server.zig`, `telemetry.ts`, or
